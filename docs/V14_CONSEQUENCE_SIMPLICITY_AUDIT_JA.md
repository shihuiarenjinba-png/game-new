## 今回の改良の意図

v0.13では「初夜に仮説を立てる→翌朝見直す」という判断を追加したが、結末の差が説明文中心で、プレイヤーが選んだ報告方針がどのような記録を残したかが分かりづらかった。さらに、中間推理・最終報告・終幕で同じ教訓が繰り返され、読みづらくなる傾向があった。

そこで新しい画面を増やさず、次の変更を行った。

1. **6つの事件固有の報告結果：** 最後に `context`（事実と推測を分ける）、`protect`（匿名で再聴取を申請）、`accuse`（班長を名指し）のどれを選んだかによって、提出した記録の内容を明確に書き分けた。
2. **暫定仮説×見直し：** 初夜の仮説 `surface / system / unknown` と翌朝の判断 `revise / retain / suspend` に応じて、思い込み・見直し・保留が記録にどう残ったかを描く。**ただし仮説は証拠ではなく、真相の回収条件は一切緩めない。**
3. **誤推理の理由：** 必要な最初の記録を見逃した、別の立場の証言が足りない、無関係の問いを選んだ、証拠ペアが不適切、疑問そのものを切り捨てた――それぞれ異なる未解決の理由を表現する。**見逃した資料の中身を後から確定事項として教えない。**
4. **物語の簡潔化：** 中間見直し画面は入手済みの新情報の有無だけを短く表示し、詳細は従来どおり折りたたみの証拠欄で確認できる。重複する最終報告の総評・長い後日談を整理し、一度の終幕で同じ回収を何度も表示しない。意味のない選択肢の補足文は表示しない。
5. **UIの増殖禁止：** 既存の物語パネル一つ、通常3択、折りたたみの証拠欄、下部の保存管理のまま。新しいタブ・管理画面・ステータス一覧・課金フォームは作っていない。
6. **旧版保護：** 新規v0.14は `arcMode: responsive` と独立した保存キー `handover-room-prototype-v14`。v0.13の `deliberative` を含む旧セーブを旧ルールのまま継続する。特に初夜終了直後・翌朝の仮説見直し直前の旧セーブでは、途中の2選択を飛ばさない。

## 新しい結末が表すものと、その限界

| 分岐 | 変わること | 勝手に変えないこと |
| --- | --- | --- |
| 暫定仮説 | プレイヤーが事件をどう理解し始めたか | 過去の証拠・人物が実際に知っていた情報 |
| 仮説の見直し | 報告へ至る思考の軌跡 | 既存の人物の過去、事故の原因 |
| 正しい証拠照合 | 6つの大型ルートごとの大きな伏線回収 | 本人が話していない告白・未調査の原本 |
| 弱い証拠照合 | 未解決の理由と次に必要な調査の種類 | 未発見の真相を結末で突然明かすこと |
| 最終報告 | 実際に記録・申請・提出した方針 | 実際には確認していない雇用規則、処分、解雇 |

大筋6本×暫定仮説3×見直し3×報告方針3＝**162種類の文章上の組み合わせ**を設計した。ただし162本の独立したミステリーという意味ではない。周辺設定72種はこの上に重なるが、脚本の質や満足度を保証する数字ではない。

# 引継ぎ室 v0.6 — 大きな伏線が収束する3つの物語系統

**商用判定：HOLD。** このブランチは新しい企画構造の試作。従来の v0.1〜v0.5 と main は変更しない。

## 72本の物語ではなく「大型事件3本 × 小変化24通り」

ユーザー提案の「トーナメントのようにいくつもの伏線が最後に大きく回収されるセット」を実装するため、大きな物語の筋を**3種類**に整理した。72通りは各筋の人物・隠した理由・周辺事情・空気感を変える補助レイヤーとする。

- A **聞く前に書かれた答え**：同じ文章は口裏合わせではなく、証言前から用意された記入例だったのか
- B **二つの発言のあいだ**：停止の相談と本人の続行発言は、同じ時刻の出来事だったのか
- C **命令のない規則**：実際の規則と「全員がそう思い込んでいた規則」は一致していたのか

それぞれ、**入口の違和感 → 別人物の証言 → 一見反対の情報 → 照合できる記録 → 大きな回収**という因果関係で構成する。

```text
  伏線 A（記録） ─┐
                   ├─ 中間の解釈変更 ── 反証・別の証言 ── 大きな真相
  伏線 B（人物） ─┘                                │
  伏線 C（時間・利害） ──────────────────────────────┘
```

**ひとつでも必要な証拠が欠ければ、大回収は起こらない。** プレイヤーの知らない真実を主人公が勝手に発見しない。

## 各ルートに必要な実際の選択

| 系統 | 第一夜の記録 | 第一夜の第二証拠 | 翌朝の反対側の証言 |
|---|---|---|---|
| A | 三人の文面比較 | 班長に報告文の作成者を確認 | 真帆に「なぜ皆が同じ話をするか」を聞く |
| B | 消された停止相談 | 真帆から直接聞いた言葉 | 佐原本人へ続行以外の選択肢を尋ねる |
| C | 契約更新の掲示 | 班長に目標と納期を確認 | 真帆に雇用不安の背景を尋ねる |

大回収はあくまで「事件の主要な問いの再解釈」であり、事故の機械的な原因や刑事責任を自動で決める機能ではない。

## UI・周回・保存

- 画面は**今までの本編と証拠欄のみ**。新しいタブ、別の管理画面、常時表示のツリーは増やさない。
- 第一夜〜翌朝、最後の証拠照合という既存の流れを使用する。シーン数を水増ししない。
- 終盤は大型の真相を主役とし、匿名の封筒の筆者など小さなランダム事件の回収は簡潔な補足へ収める。
- 最初の事件はランダム。次の事件へ進むと番号を25進める。72と25は互いに素のため72周で全パターンを一度ずつ通り、序盤から3系統が交互に現れやすい。
- **v0.6の新規周回だけ**大型伏線システムを利用。v0.5以下の保存を取り込んだ場合はlegacyとして旧事件のまま継続。途中で新しい過去の出来事を捏造しない。
- 事件番号と推理途中の判断を端末内で保存する。ネットワーク・API・外部AI不要。

## テストとリリース判定

- 72ケースすべてで、必要な証拠を正しく集めれば大型回収に進めること。
- 72ケースすべてで、証拠を一つでも逃せば断定的な大型回収が発生しないこと。
- 古いセーブを読み込んでも新しい伏線が生えないこと。
- 三つの大筋と無関係な証拠で推理点が上がらないこと。
- Windows実機の文字量・長い結末のスクロール・フォーカス・DPI・保存復元・MSIXの検証は**未実施**。
- 実プレイ時間、複数回の面白さ、第三者による心理描写レビューと支払意思は**未検証**。

**残る最大の課題：** 3つの筋は意味が違うものの、現状は共通の会話と画面が多い。「別の事件を遊んだ」と感じるかは第三者試遊で確認する。効果が弱い場合は数字だけ増やすのでなく、ルート固有の会話と人物行動を追加する。

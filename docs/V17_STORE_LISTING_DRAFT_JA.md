### 商品説明案

事故の報告書に並んだ、似すぎた言葉。記録に残った説明が同じでも、三人の見ていた出来事が同じとは限らない。

『引継ぎ室』は、集めた手がかりから仮説を立て、翌朝の聞き取りで見直し、最後に証言の関係を確かめる短編心理ミステリーです。

資料の読み方と、誰に何を尋ねたかによって、調査で確認できる範囲が変わります。確かめきれないことを断定せず、報告書に何を残すかも、あなたが選びます。

大きな主題は6種類。それぞれの事件設定にも違いがあります。ただし、72種類の設定が72本の独立した長編を意味するわけではありません。ひとつの物語画面、選びやすい選択肢、後から読み返せる折りたたみ証拠欄で、落ち着いて考えながら進められます。

ネット接続やAI生成の回答をゲーム進行に利用しない設計です。記録は端末内に保存し、JSONファイルへの書き出し・読み込みに対応します。

**注意：** 内容と機能は開発版に基づく記述です。正式なWindows MSIX実機試験および第三者の試遊評価後に必要な修正を反映してください。

### 特徴（ストア箇条書き候補）

- 集めた手がかりを照合し、推理の根拠を考える
- 第一夜の仮説を、翌朝の証言を踏まえて見直す
- 推理と報告方針によって、結末の説明が変わる
- 6つの大きな事件ルートと72種類の設定の組み合わせ
- ネット接続不要の単独プレイ設計、端末内セーブとJSON書き出し

## Microsoft Storeで実際に照合するもの

この作業ではPartner Centerの当該ゲーム製品が**未登録かもしれない**。ほかのOffice系アプリの製品Identityを転用しない。

1. Partner Centerで「引継ぎ室」が実際に作成済みか確認。なければ所有者の判断で新製品を作り製品名を予約。
2. Product Identity に表示される `Package/Identity/Name` と `Publisher` の**完全な表記**、`Package Family Name`、Store IDを確認。
3. 当該製品の値を専用Windows QA環境で入力し、`npm run audit:msix` → `npm run build:msix` → `npm run verify:msix:win` を実行。
4. Windows App Certification Kit／実機インストールをパスするまでアップロードしない。
5. 商品ページの文言・画像・価格・年齢レーティングとアプリの実態が一致することを別途確認し、まず下書きに留める。

## MSIXと配布の注意

Microsoft StoreはMSIX／MSIXUPLOADを受け付け、Store掲載・認証後にStore側で署名する。ローカル配布で署名なしMSIXがそのまま安全にインストールできるわけではない。

また `electron-builder` v27のMSIXターゲットはベータ。設定ファイルと出力ファイルの存在のみではStore受入・パッケージ起動を保証できない。

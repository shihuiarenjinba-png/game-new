## 今回実装したもの

### 1. 共通UIを維持した文章編集

これまでの表示は「本編＋事件設定＋大型伏線＋人物の反応＋調査の振り返り」を一度に連結しており、特に最終推理中・結末で長いスクロールが発生しやすかった。

新しい `reading-v10.js` は **v0.9 immersiveモード限定**で、以下のように情報を場面に合わせて整理する。

- 序盤：本編＋事件の雰囲気＋人物の短い反応
- 記録室：調べる目的を優先
- 聞き取り：本編＋実際に得た証拠に応じた物語の変化＋人物の反応
- 推理の3段階：すでに読んだ背景説明を毎回連結せず、その段階の設問だけを表示
- 最終報告：選んだ証拠から言える範囲に集中
- 結末：回収できた大きな真相（または未解決）を中心にし、共通の長い後日談と重ねない
- 新規3ルートで重なっていた「大きな回収」の見出しを重複表示しない
- すべての証拠は既存の折りたたみ証拠欄に保持する。本文を短くするために証拠取得や推理評価を変更しない。

表示の行間・選択肢の上下余白を調整し、デスクトップでは証拠欄を画面内に追従させる。新しいタブや常設管理画面は作らない。

**旧モードの文章は変更しない。** 既存のv0.9 `immersive` セーブの事実・分岐・結末も変えず、表示時だけ編集する。

### 2. Windows Edgeを使った操作検査

Windows GitHub-hosted runner にインストールされた Edgeをヘッドレス起動する `scripts/windows-edge-smoke.cjs` を追加した。

- 6つの大型ルートそれぞれの固定テスト事件を開く
- 第一夜の5判断、翌朝の聞き取り、3段階の推理、最終報告まで、UIのボタンを実際にクリックする
- 保存されたケース番号が変わらないこと、最終画面に適切な大型の回収があること、証拠欄が存在すること、次の事件へ進む操作が存在することを確認する
- デスクトップ 1366px幅の6ルートと、モバイル相当390px幅の2ルートを検査
- 文書全体の横スクロールが発生していないことを確認
- 代表する3画面のPNG画像を生成し、PNG構造・寸法・SHA-256をCIログへ出す

**限界：** GitHub-hostedの仮想Windows環境でのEdgeヘッドレス動作。個人のWindows 11 PC、125%/150% DPI、タッチ・キーボード、Electron、MSIXの実機検証や本物の購入者の試遊は含まれない。

### 3. GitHubのスクリーンショット保存制限

GitHub Actionsのアーティファクトストレージ容量上限により、画像アップロードは失敗した（ゲーム自体の描画テストは成功）。

検証を常に失敗扱いにしないため、アップロードは一旦削除した。代わりにPNGを生成・検査し、寸法とハッシュをログへ残す。**PNG本体はActionsの一時実行環境にあり、ユーザーが後からダウンロードできると主張しない。**

画像の永続保存は、容量が確保されてから復活させるか、実際のWindows PCでローカルに収集する。

## QA結果で言い切れること

- Nodeの物語・セーブ・推理・ランダム経路テスト：既存の回帰試験を維持
- Windows EdgeのUI自動操作：6つの大型事件の代表経路、デスクトップ表示、390px幅をチェック
- 旧版セーブの意味：新しい描画編集によって脚本の内部状態を変更しない
- **脚本の自然さ・演出の怖さ・周回したいか・売れるか：未検証**

| 場面 | 実施内容 | 合格条件 |
| --- | --- | --- |
| 初回起動 | Edge/ChromeとElectronで起動 | 不正な空画面・エラーがない |
| 画面幅 | 390/768/1366px、DPI 100/125/150% | 横はみ出し・操作不能なボタンがない |

| 操作時間 | 実際のプレイ時間と読了時間 | 価格との釣り合いを評価できる |

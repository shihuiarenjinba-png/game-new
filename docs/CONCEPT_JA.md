# 企画書 — 引継ぎ室（独立試作 v0.1）

## 一文で伝える体験

> 事故の責任を問うために工場を訪れた外部調査員。全員が同じ説明をする。誰も明確な嘘をついていないかもしれない。それでも、誰かが怖くて言えないことがある。

**ジャンル:** 現実寄り心理ミステリー × 証言と判断のアドベンチャー

**恐怖の源泉:** 意図的な驚かせ演出ではなく、沈黙、同調圧力、雇用不安、責任転嫁、善意の隠蔽、当事者への遠慮。人間が日常で選び得る行動が少しずつ不気味になる。

**当面の完成物:** 第一夜だけを含む短い選択型デモ。販売可能な製品とはみなさない。

## 世界観（ネタバレ注意）

舞台は郊外の小さな梱包工場。作業員・佐原が仕事中に負傷し休職した。報告書には「本人が自ら希望したため、作業を続行した」とある。勤務していた人々の説明が不自然に一致する。

誰かが明確に「止めるな」と命じた事実があるとは限らない。しかし、生産目標、契約更新への不安、誰かを巻き込みたくない気持ちが重なり、現場は自分たちで都合のいい一文を守ってしまう。

**テーマは犯人当てではない。** ひとりの悪人を暴いて終わる構図より「どうして反対しなかったのか」「沈黙は同意か」「誰が事実を語れる状況を作るのか」という曖昧で怖い問いを中心にする。

## 参考作品と意図的に違うこと

| 設計要素 | この新作の方針 |
|---|---|
| 舞台 | 家族の住居ではなく、利害関係がある職場 |
| 操作 | 時間を巻き戻さない。聞き方・順番・報告の判断を選ぶ |
| 謎 | 謎の侵入者、幽霊、隠れた人数ではなく、証言を揃えた動機 |
| 推理 | 違和感チェックの正答数ではなく、証拠と人への影響を考える |
| 変化 | 「正解／不正解」だけでなく、調査の結果として生まれる信頼や沈黙 |
| 怖さ | ジャンプスケアではなく、現実に起こり得る倫理的な居心地の悪さ |

## 第一夜の操作

1. 調査の態度を決める（尊重／形式／追及）。
2. 一つの記録を選んで持ち出す。
3. 同僚に一つ質問する。
4. 班長に一つ質問する。
5. 報告の扱いを決める（訂正／保留／受理）。

**現在は3×3×3×3×3=243通り、五つの結末を実装。**

分岐は確定した心理診断ではなく、作品内での対話の影響を近似するシナリオルール。現実の心理や労災対応の判断基準を再現するものではない。

### 企画段階の検証ポイント

- 同じ台詞が、繰り返すと怖い理由がプレイヤーに伝わるか。
- 「書類が怪しい＝全員が嘘つき」になっていないか。
- 調査員の選択が物語の展開に意味のある差を生むか。
- 何も断定できない結末でも、納得感や後味が残るか。
- 事件の情報を増やしても、整合性・時間軸が壊れないか。
- 無料短編と比較して、有料で提供する独自性や体験量があるか。

## 次の段階への拡張候補（未実装）

- 複数夜にわたり人物の関係性が変わる新しい会話。
- 誰かのために隠した言葉が、別の人物には裏切りとなる展開。
- 真相が一つに収束しても、人によって解釈が違うエンディング。
- テキスト中心で終わらない環境表現（無人の廊下、明かりの消えた休憩室、遠くの作業音）。
- 誰がどの情報をいつ知るかを規定した「人物別の知識台帳」で矛盾検証。
- 選択結果の個人情報を外部に送らず、端末で完結するセーブ方式の堅牢化。

## 絶対にしないこと

- 無断でSTRATEGY MARKETおよび他の既存完成作品に変更を加えない。
- STRATEGY MARKETシリーズのコードや素材をコピーしない。
- 無料の参考作品の場面・人物・具体的な仕掛けを再現しない。
- 物語の不気味さを、現実とかけ離れたAIの超能力や単なる数値エラーだけで説明しない。
- 売れる根拠がないうちに有料販売を前提に完成扱いしない。

## 制作メモ

- 独立したオリジナルのHTML/CSS/JS構成。
- 外部API、音声生成API、AIチャット、画像素材、広告・課金機能なし。
- 物語は事実確定と推測を分けることを重視する。
- 開発テスト: Node.js 20以上で \`node --test tests/story.test.cjs\`。
- HTMLは \`index.html\` を直接開ける設計。ファイルURLのストレージ可否はブラウザ環境依存。
- 公開・販売は権利、操作性、実機チェック、第三者試遊後に判断する。

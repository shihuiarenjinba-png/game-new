# v0.7 因果関係・ランダム監査

**判定：自動テストの因果条件 = PASS（現行実装のルール範囲）／有料販売 = HOLD**

## 修正した問題

1. **存在しない証拠の出現**：旧v0.6では、会話条件がそろうと未調査の「署名前の記入例」「個人の雇用更新書類」を事実として生成していた。v0.7の新規周回ではこれらを削除。調べた記録と聞いた発言のみで推理する。
2. **勝手に結末が確定**：旧版ではフラグ3つで大きな回収に進んだ。今は入口記録、支える証言、反対側の発言に加えて、プレイヤーが中央の問いを選び、証言2つを実際に比較する必要がある。
3. **シードの偏り**：連続シードを同じ大型ルートへ割り当てる方法を改め、封筒筆者・動機・小事件・空気感の要素を考慮した均等割当（3ルート各24変種）に修正。全72変種を重複なく巡り、連続する回で大型ルートが変わる。
4. **根拠のない人物の動機確定**：結末で筆者の証明と心の中の動機の立証を区別。直接裏付けがない場合に動機まで断定しない。
5. **旧セーブの改変**：v0.7は別保存キー・別モード。v0.6以前の途中経過は旧版の物語規則で再開し、過去の証言を書き換えない。

## 3つの大型回収の論理的な上限

| 大型ルート | 得られる根拠 | 言い切れないこと |
| --- | --- | --- |
| 聞く前に書かれた答え | 同一の報告文、荻野の編集説明、真帆の証言 | 他2人への配布経路、強制的な口裏合わせ |
| 二つの発言のあいだ | 消された停止相談、真帆の聞いた言葉、佐原本人の発言 | 発言順序の厳密な時刻、事故の直接原因 |
| 命令のない規則 | 部署評価の掲示、班長の納期発言、雇用への不安 | 更新規則が実際に存在しなかったという断定 |

## 自動監査

- 全72事件シードについて、大型回収へ到達可能な経路を検査。
- 72 × 3^6 = **52,488通りの調査選択の組み合わせ**で、必要な手掛かりが出たか、未選択の証言が出ていないかを検証。
- 根拠が欠ける経路、関係のない推理テーマ、弱い証拠ペアでは大型回収に進めないことを検証。
- 保存データ互換、ランダムの分布、ケース重複、UI構造も検証。
- **自動テストの限界**：文章の人間らしさ、事実の含意の妥当性、プレイヤーの満足度、実機の画面表示までは保証しない。脚本監修と実際の試遊は別途必要。

## 有料化に必要な大型ルート数の診断

**現行3系統は不足する可能性が高い。** 72通りは72本の独立した物語ではなく、共通する短い二章の背景設定の組み合わせである。

制作の暫定候補として、独立した大型ルートを**6本程度まで増やす価値を検討**し、体験量や試遊の結果が弱ければ8本以上、あるいは各ルートの質と長さの強化を検討する。6や8は市場の絶対的な最低本数ではない。

**追加ルートの合格条件：** 新しい問い、人物の知識台帳、根拠の出所と取得時刻、反証の存在、回収条件、未解決の分岐、全ランダム組み合わせでの整合性が必要。新しい人物名や背景だけでは別ルートとして数えない。

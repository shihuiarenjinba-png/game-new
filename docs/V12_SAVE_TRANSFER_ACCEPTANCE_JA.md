# 引継ぎ室 v0.12 — セーブ移行・別事件への復元検査

**状態：Windows Edge自動QA／商品化HOLD。**

## 今回の重点

v0.11ではWindows Edgeの代表3条件でキーボード入力・画面倍率・途中リロードを確認した。ただし、画面下部の「記録の管理」で実際にJSONをダウンロードし、そのファイルから元の事件へ戻す操作は未検証だった。

今回、`scripts/windows-edge-save-transfer.cjs` を追加。実際のEdgeブラウザで次の操作を行う。

1. 事件を2ステップ進め、端末内のJSONセーブを確認する。
2. 「記録をファイルに保存」をクリックし、実際にローカルへ保存されたJSONのバイト列がセーブと一致するか確認する。
3. JSONとして壊れたファイルを入力したとき、読み込みを拒否して現存セーブを変更しないことを確認する。
4. 別事件の正常なセーブを選んでも、確認ダイアログでキャンセルしたら変更されないことを確認する。
5. 事件をさらに進めた後、先ほど書き出したJSONを読み込み、同じ事件番号・履歴・証拠へ戻ることを確認する。
6. 実際にページをリロードし、復元後の情報が維持されることを確認する。
7. さらに別事件の初期セーブを取り込み、以前の事件の証拠や人物情報が表示欄に残らないことを確認する。

**注：** ファイル選択ダイアログの手動操作そのものではなく、Edgeブラウザ内のFileオブジェクトをinputへ設定して `change` を発生させる方法で検査。ダウンロード側はブラウザの実ダウンロードを使用。サーバー送信は行わない。

## 自動化と手動検査の境界

- Windows Edge自動操作はゲーム内UI／localStorage／File APIの回帰検証。
- Windows 11上の実プレイヤーによるバックアップ選択ダイアログ・保存先・OSの権限・ウイルス対策との相性は**未検証**。
- Electronビルド・正式MSIX・Store登録・署名の検証は**別工程**。
- 多周回の面白さ、6ルートの個別性、プレイ時間、価格と購入意思は**第三者試遊なしには合格にしない**。

## 商用化へ向けて残る条件

- 6ルートを初めて遊ぶ人が、各ルートで根拠を実際に理解できるか
- 正解ルートと未回収ルートの体験差があるか
- Windows PCでスクロール・文字・クリック・保存先ダイアログが自然か
- MSIXに署名しインストール・更新・アンインストールまで追跡できるか
- 想定販売価格に見合うプレイ時間・コンテンツの独自性があるか

**作品の構造は維持：** 大型ルート6種、各12設定の72事件組み合わせ。UIは本編・3択・折りたたみ証拠欄のまま。今回新しいタブや設定画面を追加していない。

**安全な変更対象：** `game-new / feature/handover-v12-save-transfer-replay-qa` のみ。STRATEGY MARKET全系統、ほかの既存作品、main、過去の開発ブランチは変更しない。
